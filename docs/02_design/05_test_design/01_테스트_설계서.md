# 테스트 설계서

## 문서 목적
회사도우미의 테스트 범위, 테스트 유형, 테스트 케이스, 완료 기준을 정의한다.

## 테스트 유형

| 유형 | 대상 | 목적 | 도구 후보 |
|---|---|---|---|
| Unit Test | 도메인/서비스 로직 | 작은 단위 검증 | JUnit, Jest |
| Integration Test | API/DB 연동 | Spring, MyBatis, PostgreSQL 연동 검증 | Spring Test |
| Contract Test | API 요청/응답 | Frontend-Backend 계약 검증 | TBD |
| E2E Test | 주요 사용자 흐름 | 폴더 생성부터 파일 저장과 산출물 생성까지 검증 | Playwright |
| AI Evaluation | AI 결과 품질 | 요약/추출 품질 검증 | 수동+자동 평가 |

## 주요 테스트 시나리오

| ID | 시나리오 | Given | When | Then | 우선순위 |
|---|---|---|---|---|---|
| TC-FOLDER-001 | 개인 폴더 생성 | 메인 화면에 진입했다 | 개인 폴더를 생성한다 | 사이드바 트리에 표시된다 | MVP |
| TC-FOLDER-002 | 폴더 잠금 실패 | 비밀번호가 설정된 폴더가 있다 | 잘못된 비밀번호를 입력한다 | 오류 메시지가 표시되고 파일 목록은 보이지 않는다 | MVP |
| TC-FOLDER-003 | 공유 세션 입장 | 공유 세션 이름이 있다 | 별칭과 필요한 경우 비밀번호를 입력한다 | 공유 세션 상세로 이동한다 | MVP |
| TC-FILE-001 | 파일 저장 | 폴더가 열려 있다 | md 파일을 생성하고 저장한다 | Markdown 원본과 HTML 렌더링 결과가 저장된다 | MVP |
| TC-AUDIO-001 | 공통 음성 처리 | 녹음 파일이 있다 | 음성을 업로드하고 STT를 실행한다 | 원문 텍스트가 저장되고 회의록/시간 기록 생성에 재사용된다 | MVP |
| TC-MEETING-001 | 회의록 요약 생성 | 녹음 파일이 있다 | 파일을 업로드한다 | 전사/요약 결과가 생성된다 | MVP |
| TC-TIME-001 | 시간 기록 가중치 생성 | 원문 텍스트가 있다 | 시간 기록 생성을 실행한다 | 활동 시간, 활동 유형, 중요도/집중도 후보가 생성된다 | 후보 |
| TC-DEADLINE-001 | 데드라인 추출 | 요약 내용에 마감일이 있다 | AI 추출을 실행한다 | 캘린더에 후보가 표시된다 | MVP |
| TC-REPORT-001 | 주간 보고 생성 | 기간 내 기록이 있다 | 주간 보고 생성을 실행한다 | 보고서 초안이 생성된다 | MVP |

## 완료 기준

- MVP 요구사항의 주요 성공/실패 케이스가 작성되어 있다.
- 폴더 접근 제한, 파일 업로드, AI 실패 케이스가 포함되어 있다.
- 공통 음성 처리 결과가 회의록과 시간 기록으로 분기되는 흐름을 검증한다.
- 테스트 데이터와 기대 결과가 명확하다.
- TDD 대상 기능은 실패 테스트부터 작성한다.
