# 인프라 구성도

## 문서 목적

- 회사도우미의 개발/검증용 인프라 방향을 정의한다.
- 기능이 아직 확정되지 않은 초기 단계이므로 EC2 상시 운영보다 로컬 Docker 기반 개발 환경을 우선한다.
- 팀원 1명이 함께 접속할 수 있는 구조를 고려하되, GitLab/Nexus 같은 무거운 구성은 단계적으로 도입한다.

## 현재 결정 사항

| 구분 | 결정 | 이유 |
|---|---|---|
| Git 저장소 | GitHub 사용 | GitLab 자체 운영은 초기 단계에서 리소스와 운영 부담이 큼 |
| GitHub 공개 범위 | public 또는 private 검토 | public 사용 시 `.env`, API Key, DB 비밀번호 업로드 금지 |
| 개발 실행 환경 | 로컬 노트북 Docker Compose 우선 | EC2 비용 없이 빠르게 실험 가능 |
| 팀원 접속 | Tailscale 우선 검토 | 집 고정 IP/포트포워딩 없이 팀원 접속 가능 |
| DB | PostgreSQL Docker 컨테이너 | 프로젝트 표준 DB와 일치 |
| AI Worker | Python AI Worker 우선 | Spring API와 AI 실행 방식을 분리 |
| AI 실행 방식 | 외부 API 또는 로컬 모델 검토, 터미널 브리지는 개발 실험용 | 운영 안정성과 보안 경계를 위해 adapter 구조 필요 |
| Reverse Proxy | Caddy 또는 Traefik 검토 | 여러 개발 서비스를 하나의 진입점으로 묶기 위함 |
| GitLab | 제외 | 로컬 노트북에서 무겁고 현재 GitHub로 충분함 |
| Nexus | 2단계 선택 도입 | Maven/npm 사내 패키지 저장소가 실제로 필요해진 뒤 추가 |

## 로컬 개발 환경 1단계

```text
[GitHub]
   |
   | git clone / pull / push
   v
[개발자 노트북]
   |
   v
[Docker Compose]
   ├── React Dev Server
   ├── Spring Boot Server
   ├── PostgreSQL
   └── Python AI Worker
       ├── External AI API Adapter
       ├── Local Model Adapter
       └── Terminal Bridge Adapter (dev only)
```

### 1단계 포함 범위

- React 개발 서버
- Spring Boot 개발 서버
- PostgreSQL
- Python AI Worker 기본 구조
- AI provider adapter 설정
- `.env` 기반 환경 변수 분리
- Docker volume 기반 DB 데이터 보존
- DB 백업/복구 방식 문서화

### 1단계 제외 범위

- GitLab 자체 운영
- Nexus 자체 운영
- 운영용 HTTPS/도메인 공개
- 고가용성, 이중화, 자동 스케일링
- 운영 DB 백업 자동화

## 팀원 접속 구조

팀원 1명과 함께 개발할 때는 Tailscale을 우선 사용한다.

```text
[팀원 PC]
   |
   | Tailscale VPN
   v
[개발자 노트북 Tailscale IP]
   |
   v
[Docker Compose 서비스]
   ├── React: 3000 또는 reverse proxy 경유
   ├── Spring API: 8080 또는 reverse proxy 경유
   └── PostgreSQL: 외부 직접 노출 금지
```

### Tailscale을 우선하는 이유

- 집 공인 IP가 바뀌어도 접속 경로가 유지된다.
- 공유기 포트포워딩을 열지 않아도 된다.
- GitHub public 저장소와 별개로 개발 서버는 팀원에게만 제한적으로 공유할 수 있다.
- GitLab/Nexus/DB 같은 관리 도구를 인터넷에 직접 노출하지 않아도 된다.

## 로컬 개발 환경 2단계

필요성이 확인되면 개발 편의 도구를 추가한다.

```text
[Docker Compose]
   ├── reverse-proxy: Caddy 또는 Traefik
   ├── frontend: React
   ├── backend: Spring Boot
   ├── db: PostgreSQL
   ├── db-admin: Adminer 또는 pgAdmin
   ├── ai-worker: Python Worker
   └── nexus: Nexus Repository OSS (선택)
```

### Nexus 도입 기준

다음 조건 중 하나 이상이 생기면 Nexus 도입을 검토한다.

- 공통 Java 라이브러리를 직접 배포해야 한다.
- npm 사내 패키지를 직접 배포해야 한다.
- 외부 의존성 캐시가 필요하다.
- 팀원이 늘어나 의존성 버전 관리가 중요해진다.

현재는 GitHub와 공개 패키지 저장소를 그대로 사용하는 편이 단순하다.

## 외부 데모 공개 구조

개발 서버를 외부 사람에게 잠깐 보여줘야 할 때만 Cloudflare Tunnel을 검토한다.

```text
Internet
   |
   v
[Cloudflare Tunnel]
   |
   v
[개발자 노트북]
   |
   v
[Reverse Proxy]
   ├── React
   └── Spring API
```

### 외부 공개 시 주의 사항

- PostgreSQL은 외부에 직접 공개하지 않는다.
- Adminer, pgAdmin, Nexus 같은 관리 화면은 공개하지 않는다.
- 공개가 필요하면 Cloudflare Access, Tailscale ACL, Basic Auth 등 추가 인증을 붙인다.
- 공개 URL은 데모 기간에만 열고 사용 후 닫는다.

## 운영 환경 방향

운영 배포는 기능과 사용자가 확인된 뒤 EC2 또는 다른 클라우드로 이전한다.

```text
[Internet]
   |
   v
[DNS]
   |
   v
[Reverse Proxy / Load Balancer]
   |
   v
[Frontend Static Hosting]
   |
   v
[Spring Boot API Server]
   |            \
   v             v
[Managed PostgreSQL]   [AI Worker]
                         |
                         v
                  [External AI API or Local LLM]
```

### 운영 전환 조건

- 팀원 외 실제 사용자가 생긴다.
- 노트북이 꺼져도 서비스가 유지되어야 한다.
- HTTPS 도메인, 백업, 장애 대응이 필요해진다.
- AI API Key, 사용자 데이터, 파일 업로드 데이터가 운영 수준으로 관리되어야 한다.

## 환경별 설정 항목

| 환경 | Frontend | Backend | DB | AI | 접속 방식 | 비고 |
|---|---|---|---|---|---|---|
| local | React Dev Server | Spring Boot | PostgreSQL Docker | 후순위 | localhost | 개인 개발 |
| team-dev | React Dev Server | Spring Boot | PostgreSQL Docker | 후순위 | Tailscale | 팀원 1명 공유 |
| demo | React Dev Server 또는 build 결과 | Spring Boot | PostgreSQL Docker | 후순위 | Cloudflare Tunnel 검토 | 임시 공개만 허용 |
| prod | 정적 호스팅 검토 | Spring Boot 운영 배포 | Managed PostgreSQL 검토 | Python Worker 또는 외부 API | DNS + HTTPS | 기능 검증 후 결정 |

## 보안 규칙

- GitHub public 저장소에는 `.env`, API Key, DB 비밀번호, Tailscale 인증 키를 올리지 않는다.
- DB 포트는 기본적으로 로컬 또는 Tailscale 내부에서만 접근한다.
- 개발 서버 공개가 필요해도 DB와 관리 도구는 공개하지 않는다.
- Docker volume 백업 파일은 저장소에 커밋하지 않는다.
- 팀원 접속 권한은 Tailscale 계정/ACL 기준으로 관리한다.

## 미결정 사항

- GitHub 저장소를 public으로 할지 private으로 할지 결정 필요
- Reverse Proxy를 Caddy로 할지 Traefik으로 할지 결정 필요
- DB 관리 도구를 Adminer로 할지 pgAdmin으로 할지 결정 필요
- Nexus 도입 시점 결정 필요
- Cloudflare Tunnel 사용 여부 결정 필요
- 운영 환경을 EC2로 갈지, Render/Fly.io/Vercel/RDS 조합으로 갈지 결정 필요
