# 아키텍처 설계서

## 문서 목적
회사도우미의 시스템 구성, 인프라, 주요 흐름을 정의한다.

## 기술 스택 초안

| 영역 | 기술 | 비고 |
|---|---|---|
| Frontend | React | 화면 구현 |
| Backend | Spring Boot | 인증, API, 비즈니스 로직 |
| Persistence | MyBatis | SQL 중심 데이터 접근 |
| Database | PostgreSQL | 주요 업무 데이터 저장 |
| AI 처리 | Python AI Worker + Provider Adapter | STT, 요약, 추출, 리뷰, 시간 기록 가중치 |
| SCM | GitHub | 코드 관리 |
| 협업 | Notion | 기획/문서 협업 |

## 시스템 구성도

```text
[Browser]
   |
   v
[React Frontend]
   |
   v
[Spring Boot API]
   |         \
   v          v
[PostgreSQL] [Python AI Worker]
              |
              v
        [External AI API / Local Model / Dev Terminal Bridge]
```

## 주요 흐름

### 공통 음성 처리

```text
사용자 녹음/파일 업로드
-> Spring API 파일 접수
-> ai_jobs 생성
-> STT 결과 생성
-> 원문 텍스트 저장
-> 목적별 Agent 분기
```

### 회의록 요약

```text
공통 음성 처리 결과
-> MeetingMinutesAgent
-> 안건/결정사항/할 일/담당자/마감일 추출
-> DB 저장
-> 화면 표시/다운로드
```

### 시간 기록 대시보드

```text
공통 음성 처리 결과
-> TimeLogAgent
-> 시간대/활동 유형/중요도/집중도 가중치 후보 생성
-> 사용자 확인/수정
-> 일간/주간 대시보드 저장
```

### 데드라인 추출

```text
회의록/세션 기록 저장
-> AI 마감일 추출
-> 후보 마감일 생성
-> 사용자 확인
-> 캘린더 등록
-> 메인 페이지 임박 항목 표시
```

## 설계 결정 필요 사항

- 1차 AI 실행 방식을 외부 API로 할지 로컬 모델로 할지 여부
- 터미널 세션 브리지를 개발 실험용으로 둘지 여부
- Agent 프레임워크를 직접 구현할지 LangGraph 등을 쓸지 여부
- 파일 저장소 위치
- 폴더 비밀번호 해시 방식
- 실시간 공유: WebSocket, SSE, polling 중 선택
- 배포 환경: 로컬, 사내 서버, 클라우드 중 선택
