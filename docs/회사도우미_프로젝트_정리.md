# 회사도우미 프로젝트 정리

## 문서 목적
- 회사 업무를 보조하는 AI 기반 웹 서비스 아이디어와 초기 요구사항을 정리한다.
- 최종 사용처: 내부 검토 / 개발 범위 정의 / 화면 설계 준비 / 학습 계획 정리

## 한 줄 결론
- `회사도우미`는 로그인 기반 업무 보조 서비스로, 회의록/주간보고/데드라인/코드리뷰/시간기록/기술리서치를 AI와 회사 표준 기술 스택으로 통합하는 프로젝트다.

## 핵심 요약
- 회원만 접속 가능한 웹 서비스이며, 로그인 페이지와 메인 페이지가 필요하다.
- 개인 세션과 공유 세션 방을 제공하고, 공유 세션에서는 캔바/노션처럼 텍스트나 이미지을 함께 공유할 수 있어야 한다.
- 핵심 기능은 회의록 요약, 주간보고 작성, AI 기반 데드라인 추출/알림/결과물 검토, AI 코드 리뷰, 시간 상담 기록, 기술/논문 리서치 자동화다.
- 기술 스택은 회사 기준에 맞춰 GitHub, Spring, React, MyBatis, PostgreSQL을 우선 사용한다.
- AI 기능은 Python 기반 처리부터 검토하고, LangGraph, 로컬 LLM, Ollama, MCP, Agent, Skills, Sub Agent 사용법을 학습 범위에 포함한다.

## 확정된 내용
- 프로젝트 이름: 회사도우미
- 로그인 기능 필요
- 회원만 사이트 접속 가능
- 회원 룰/권한 정책은 현재 없음
- 기본 화면: 로그인 페이지, 메인 페이지
- 세션 구조:
  - 개인 세션
  - 공유 세션 방
  - 공유 세션 방 초대 기능
  - 공유 세션 내 텍스트/그림 공유 기능
- 기술 스택:
  - GitHub
  - Spring
  - React
  - MyBatis
  - PostgreSQL
  - AI 처리 우선 검토 언어: Python
- 협업 툴: Notion
- 개발 시 코드 컨벤션과 GitHub 브랜치 전략을 별도 정의해야 한다.
- 회의는 월, 화, 수 20시에 할 예정(변경 가능성 있음)

## 주제별 정리

### 1. 서비스 기본 구조
- 논의 내용:
  - 회사 업무를 돕는 AI 기반 웹 서비스를 만든다.
  - 로그인한 회원만 사이트에 접근할 수 있다.
  - 별도 회원 등급이나 권한 룰은 현재 정의하지 않는다.
- 현재 상태:
  - 아이디어/요구사항 초안 단계
- 영향:
  - 인증/인가, 세션 관리, 사용자별 데이터 분리, 공유 방 초대 구조가 초기 설계의 핵심이다.

### 2. 세션 기능
- 논의 내용:
  - 개인 세션은 사용자가 혼자 업무 기록, AI 요약, 상담 기록 등을 남기는 공간이다.
  - 공유 세션 방은 다른 사용자를 초대하여 텍스트나 그림을 함께 공유하는 공간이다.
  - 공유 방식은 Canva나 Notion처럼 협업형 인터페이스를 참고한다.
- 현재 상태:
  - 기능 방향만 정의됨
- 영향:
  - 실시간 협업이 필요한지, 단순 저장/동기화 공유인지에 따라 기술 난이도가 크게 달라진다.
  - WebSocket, SSE, 충돌 처리, 히스토리 저장 방식 검토가 필요하다.

### 3. 회의록 요약 작성
- 논의 내용:
  - 녹음 파일을 업로드하거나 녹음한다.
  - 녹음 데이터를 텍스트로 변환한다.
  - AI가 회의 내용을 요약한다.
  - 결과를 Excel 또는 한글로 출력한다.
  - 결과물을 공유할 수 있어야 한다.
- 현재 상태:
  - 주요 업무 자동화 후보
- 영향:
  - 음성 인식, 요약 프롬프트, 산출물 템플릿, 파일 내보내기 기능이 필요하다.

### 4. 주간 보고 작성
- 논의 내용:
  - 개인/공유 세션 기록, 회의록, 시간 기록, 데드라인 데이터를 바탕으로 주간 보고서를 자동 작성한다.
  - 보고서 출력 형식은 추후 정한다.
- 현재 상태:
  - 기능명만 정의됨
- 영향:
  - 주간 데이터 수집 기준, 보고서 템플릿, 사용자 수정 플로우가 필요하다.

### 5. AI 데드라인 추출 및 관리
- 논의 내용:
  - AI 요약 결과에서 일정/마감 정보를 추출한다.
  - 추출한 데드라인을 캘린더 형식으로 자동 입력한다.
  - 메인 페이지에서 임박한 데드라인을 표시한다.
  - 알림 기능이 필요한지 검토한다.
  - 데드라인 전까지 결과물을 AI가 자동 검토하는 기능을 고려한다.
- 현재 상태:
  - 화면 설계 시 와이어프레임과 목업 필요
- 영향:
  - 캘린더 UI, 마감 임박 기준, 알림 채널, 결과물 업로드/검토 기준이 필요하다.

### 6. AI 코드 리뷰
- 논의 내용:
  - GitHub와 연동하여 AI 코드 리뷰를 수행한다.
  - CodeRabbit 같은 서비스를 참고한다.
  - 코드 변경 히스토리를 기록한다.
  - As-Is / To-Be 비교표와 첨언을 남긴다.
  - 개발 자동화 확장 가능성을 검토한다.
- 현재 상태:
  - 확장 기능 후보이나 기술 난이도 높음
- 영향:
  - GitHub App/OAuth, PR diff 수집, 리뷰 코멘트 생성, 코드 히스토리 저장, 보안 검토가 필요하다.

### 7. 시간 상담 및 기록 대시보드
- 논의 내용:
  - 사용자가 하루 동안 한 일을 녹음한다.
  - 녹음 내용을 텍스트로 변환한다.
  - DB에 히스토리로 기록한다.
  - 하루 기록 대시보드와 주간 대시보드를 만든다.
- 현재 상태:
  - 자동화하면 좋은 기능으로 정의됨
- 영향:
  - 음성 입력, 활동 분류, 시간대별 기록, 시각화 대시보드가 필요하다.

### 8. 새로운 개념/논문/기술 스택 리서치
- 논의 내용:
  - 새로운 개념을 찾거나 논문 리서치를 자동화한다.
  - 새로운 기술 스택 정의를 자동화한다.

### 일정 스테퍼 화면 설계
- 목적:
  - 회의, 보고서, 데드라인, 코드리뷰, 리서치 같은 업무 일정을 단순 목록이 아니라 진행 단계로 보여준다.
  - 사용자가 현재 일정이 어느 단계에 있는지, 다음에 무엇을 해야 하는지 빠르게 확인할 수 있게 한다.
- 적용 위치:
  - 메인 페이지의 `임박 데드라인` 영역
  - 캘린더 상세 보기
  - 회의록 요약/주간 보고/코드 리뷰 같은 산출물 작업 상세 화면
- 기본 스테퍼 예시:
  1. 일정 등록
  2. 자료 수집
  3. AI 초안 생성
  4. 사용자 검토
  5. 최종 산출물 완료
- 일정 유형별 스테퍼 예시:

| 일정 유형 | 스테퍼 단계 | 메모 |
|---|---|---|
| 회의록 | 회의 예정 -> 녹음/파일 업로드 -> 전사 완료 -> AI 요약 완료 -> 공유/출력 완료 | 회의 전/후 상태를 모두 표시 |
| 주간 보고 | 기간 선택 -> 소스 수집 -> AI 초안 생성 -> 사용자 수정 -> 제출/다운로드 완료 | 보고서 마감일과 연동 |
| 데드라인 | 일정 추출 -> 캘린더 등록 -> 임박 알림 -> 결과물 업로드 -> AI 검토/완료 | 알림 여부는 추후 결정 |
| 코드 리뷰 | GitHub 연결 -> PR/커밋 선택 -> AI 리뷰 생성 -> 사용자 확인 -> 반영/종료 | GitHub 연동 방식 결정 필요 |
| 리서치 | 주제 등록 -> 자료 수집 -> 요약/비교 -> 기술 선택 이유 정리 -> 참고 링크 저장 | 출처 신뢰도 표시 필요 |

- 스테퍼 상태값:
  - `대기`: 아직 시작하지 않은 단계
  - `진행 중`: 현재 작업 중인 단계
  - `완료`: 완료된 단계
  - `보류`: 사용자 확인이나 외부 자료가 필요한 단계
  - `기한 초과`: 마감일을 넘긴 단계
- UI 메모:
  - 완료 단계는 체크 아이콘과 완료 일시를 표시한다.
  - 현재 단계는 강조 색상과 다음 행동 버튼을 함께 표시한다.
  - 보류 단계는 `확인 필요 사항` 링크 또는 메모를 연결한다.
  - 기한 초과 단계는 메인 페이지와 캘린더에서 우선 노출한다.
  - 모바일에서는 세로형 스테퍼, 데스크톱에서는 가로형 또는 좌측 세로형 스테퍼를 검토한다.
