# 문서 작성 규칙

## 목적
팀원이 문서를 같은 방식으로 작성하고 유지하기 위한 규칙을 정의한다.

## 파일명 규칙

가능하면 다음 형식을 사용한다.

```text
NN_문서명.md
```

예시:

```text
01_요구사항_정의서.md
02_화면_설계서.md
03_API_설계서.md
```

## 문서 기본 구조

```md
# 문서 제목

## 문서 목적

## 내용

## 미결정 사항

## 변경 이력
```

## 상태 표기

| 상태 | 의미 |
|---|---|
| 초안 | 처음 작성한 상태 |
| 검토 중 | 팀 리뷰 중 |
| 확정 | 현재 기준으로 확정 |
| 변경 필요 | 수정이 필요한 상태 |
| 보류 | 나중에 다시 결정 |

## 요구사항 추적 규칙

기능은 가능하면 다음 문서와 연결한다.

| 연결 대상 | 예시 |
|---|---|
| 요구사항 | `REQ-SESSION-001` |
| 화면 | `SCR-SESSION-001` |
| API | `API-SESSION-001` |
| 테스트 | `TC-SESSION-001` |
| DB | `sessions` |

## 변경 이력 규칙

중요 문서에는 하단에 변경 이력을 둔다.

```md
## 변경 이력

| 일자 | 변경 내용 | 작성자 |
|---|---|---|
| 2026-05-04 | 초안 생성 | 홍길동 |
```

## 리뷰 기준

- 문서 목적이 명확한가
- 미결정 사항이 숨겨져 있지 않은가
- 요구사항, 화면, API, DB, 테스트가 연결되는가
- 팀원이 읽고 다음 행동을 할 수 있는가
