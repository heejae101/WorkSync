# 폴더 세션 및 파일 저장 방식 분석

## 문서 목적

- 로그인/회원가입 대신 폴더 기반 개인/공유 세션을 사용하는 요구사항을 정리한다.
- 사이드바 폴더 구조, 폴더 비밀번호, 공유 세션 별칭 기록 방식을 설계 후보로 연결한다.
- `.md`, `.html`, `.json` 파일을 어떤 기준으로 저장하고 어떤 라이브러리를 검토할지 정리한다.

## 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 인증 방식 | MVP에서는 로그인/회원가입 제외 | 계정 설계보다 폴더 기반 세션 기능 검증을 먼저 진행 |
| 세션 구분 | 폴더 단위 구분 | 사이드바 트리와 개인/공유 세션 모델을 같은 구조로 관리 가능 |
| 개인 세션 | 사용자가 만든 개인 폴더 | 별도 계정 없이 개인 작업 공간 제공 |
| 개인 접근 제한 | 폴더 비밀번호 선택 설정 | 계정 없이 최소한의 접근 제한 제공 |
| 공유 세션 | 세션 이름, 선택 비밀번호, 별칭으로 입장 | 누가 작성했는지 별칭 기준으로 기록 |
| 비밀번호 저장 | 원문 저장 금지, 해시 저장 | 저장소 유출 시 비밀번호 원문 노출 방지 |

## 미결정 사항

| 항목 | 선택지 | 검토 필요 이유 |
|---|---|---|
| 비밀번호 해시 알고리즘 | BCrypt, Argon2 | Spring Security 적용 범위와 난이도 확인 필요 |
| 파일 본문 저장 위치 | PostgreSQL TEXT/JSONB, 로컬 파일, S3 계열 | MVP 단순성과 추후 대용량 파일 처리 기준 충돌 |
| 에디터 라이브러리 | Toast UI Editor, TipTap, Milkdown | Markdown 중심인지 구조화 문서 중심인지에 따라 달라짐 |
| HTML 저장 기준 | 저장 시 생성, 조회 시 생성 | 캐시 일관성과 구현 단순성 비교 필요 |
| JSON 저장 기준 | 메타데이터/AI 결과만 저장, 에디터 문서 모델까지 저장 | 협업 편집 확장 여부에 따라 달라짐 |

## 저장 모델 후보

### 후보 A: Markdown 원본 중심

| 저장 필드 | 역할 |
|---|---|
| `content_markdown` | 사용자가 작성한 원본 문서 |
| `content_html` | 화면 미리보기와 출력용 렌더링 캐시 |
| `content_json` | AI 분석 결과, 일정/마감일, 코드 리뷰 결과 같은 구조화 데이터 |

장점:

- 사람이 읽고 수정하기 쉽다.
- `.md` 파일 저장 요구사항과 가장 잘 맞는다.
- MVP 구현이 단순하다.

단점:

- 실시간 공동 편집, 리치 텍스트 속성 보존은 제한적이다.
- HTML 캐시가 Markdown 원본과 어긋나지 않도록 저장 규칙이 필요하다.

### 후보 B: JSON 문서 모델 중심

| 저장 필드 | 역할 |
|---|---|
| `content_json` | 에디터의 문서 원본 |
| `content_html` | 렌더링 결과 |
| `content_markdown` | 내보내기 또는 호환용 변환 결과 |

장점:

- 리치 텍스트 편집과 협업 편집 확장에 유리하다.
- 문서 구조를 블록 단위로 다루기 좋다.

단점:

- Markdown 파일을 원본으로 다루는 요구와 맞지 않을 수 있다.
- Markdown 변환 품질과 라이브러리 의존성이 중요해진다.

## 라이브러리 후보

| 후보 | 용도 | 장점 | 리스크 | MVP 판단 |
|---|---|---|---|---|
| Toast UI Editor | React Markdown/WYSIWYG 에디터 | Markdown 작성, HTML 미리보기 흐름이 단순함 | JSON 문서 모델은 별도 설계 필요 | 1순위 후보 |
| TipTap | ProseMirror 기반 리치 텍스트 에디터 | JSON 문서 모델과 협업 편집 확장에 유리함 | Markdown 원본 중심 요구와는 추가 변환 필요 | 2순위 후보 |
| Milkdown | Markdown 중심 ProseMirror 에디터 | Markdown과 구조화 편집의 중간 지점 | 팀 학습 비용 확인 필요 | 검토 후보 |
| markdown-it 또는 commonmark 계열 | 서버/클라이언트 Markdown 렌더링 | Markdown을 HTML로 변환하기 좋음 | XSS 방지를 위한 sanitizer 별도 필요 | 보조 라이브러리 후보 |
| DOMPurify | HTML sanitizer | HTML 렌더링 시 스크립트 삽입 방지 | 서버 측 사용 시 설정 확인 필요 | 보조 라이브러리 후보 |

## MVP 권장안

MVP는 후보 A를 우선한다.

1. 파일 원본은 Markdown을 기본으로 저장한다.
2. HTML은 저장 시 생성한 렌더링 캐시로 둔다.
3. JSON은 AI 결과, 파일 메타데이터, 일정/마감일 같은 구조화 데이터로 둔다.
4. 에디터는 Toast UI Editor를 1차 후보로 검토한다.
5. HTML 출력 전 sanitizer를 적용한다.
6. 실시간 공동 편집이 필요해지면 TipTap/ProseMirror/Yjs 기반으로 재검토한다.

## 데이터 저장 초안

```text
folders
├── id
├── parent_id
├── name
├── type: PERSONAL | SHARED
├── password_hash
└── status

session_files
├── id
├── folder_id
├── name
├── extension: md | html | json
├── content_markdown
├── content_html
├── content_json
└── status

session_members
├── id
├── folder_id
├── alias
└── role
```
